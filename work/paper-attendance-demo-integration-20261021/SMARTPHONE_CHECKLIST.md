# 紙出席簿読み取り デモ配信前スマホ確認手順

対象: DEV Hostingへ配信したデモ候補。実会員・本番環境は使用しない。

## 事前条件

1. DEV専用の先生アカウントとテスト会員を用意する。
2. 端末を十分に充電し、他の重いアプリを終了する。
3. 安定したWi-Fiを使用する。初回はPyodide、NumPy、Pillowを取得するため通信量と時間が増える。
4. 検証帳票は既存の27セル正解画像を使用する。
5. ブラウザ、OS、端末名、搭載メモリ、空き容量を記録する。

## 基本測定

1. 紙の出席記録取込画面を開き、Firebase認証済みであることを確認する。
2. 検証帳票を選択する。選択直後に自動登録やFirestore書込みが起きないことを確認する。
3. 「画像補正＋AI読み取り」を押す。
4. 次を記録する。
   - プログレスバーが0～100%で更新されるか。
   - 処理段階の説明が変化するか。
   - 経過時間が約1秒ごとに増えるか。
   - 画面スクロールやOS操作が固まらないか。
   - OSのメモリ警告、ブラウザ再読み込み、Worker停止がないか。
   - 画像補正完了までの時間、Gemini完了までの合計時間。
5. 完了後、400セルが表示され、候補／要確認／空白が33／0／367、正解27セルがすべて候補化されていることを確認する。
6. カード361・362・381・382を開き、文字欠けと隣接セル混入がないことを確認する。

## キャンセル確認

1. 同じ画像で再度処理を開始する。
2. 横罫線追跡中または縦交点算出中に「処理をキャンセル」を押す。
3. 数秒以内に経過時間が停止し、「画像処理をキャンセルしました」と表示されることを確認する。
4. 再び実行でき、前回の中断状態が結果へ混入しないことを確認する。
5. Gemini通信中にもキャンセルし、通信が中断されることを確認する。

## 確認画面

1. 「認識済み」にも誤読があり得る旨と、全記入セルを照合する注意が常時表示されることを確認する。
2. 記入のある27セルを元画像と一件ずつ照合する。
3. 誤読セルを修正し、手動修正が別セル選択や再描画で消えないことを確認する。
4. 同日複数回が別セルのまま保持され、日付別集計で回数として集計されることを確認する。

## 合否基準

- 必須: 400カード、27/27、見落とし0、33／0／367。
- 必須: 進捗、経過時間、キャンセル、再実行が動作する。
- 必須: ブラウザの強制終了・自動再読み込み・OSメモリ警告がない。
- 必須: Gemini候補を全件確認でき、手動修正を保持できる。
- 記録: 前処理時間、Gemini時間、端末・OS・ブラウザ・搭載メモリ。

いずれかの必須条件を満たさない場合はデモ配信を停止し、端末情報、発生段階、経過時間、画面表示を記録する。Firestoreへの登録検証は、このチェック完了後に別途承認を得て行う。
