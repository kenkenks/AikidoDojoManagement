# 紙出席簿画像処理 高速化・省メモリ化検証

実施日: 2026-10-21

## 基準

- 固定アルゴリズム: `work/paper-attendance-preprocess-prototype.py`
- 基準実測: 248,849 ms / WASM heap 930,086,912 bytes
- 基準結果: 400カード、記入済み27/27、candidate/review/blank = 33/0/367

## 10×10マス×4区画

格子検出、縦横追跡、441交点、Coonsメッシュ構築には基準実装の関数をそのまま使用した。
変更は画像生成を4区画に分け、区画ごとにカードを書き出して画像を解放する部分だけである。

| 指標 | 基準 | 4区画 | 差 |
| --- | ---: | ---: | ---: |
| 実行時間 | 248,849 ms | 706,906 ms | 2.84倍（悪化） |
| WASM heap | 930,086,912 bytes | 624,230,400 bytes | 32.9%削減 |
| 生成カード | 400 | 400 | 同一 |
| 記入セル検出 | 27/27 | 27/27 | 同一 |
| 見落とし | 0 | 0 | 同一 |
| candidate/review/blank | 33/0/367 | 33/0/367 | 同一 |

カード361・362・381・382はブラウザ表示で文字を保持した。
statusまたはink scoreが完全一致しないカードは22件だが、判定集計と27セル検出は一致した。

## GPU用LUT設計（未実装）

精度を維持するLUTは、基準実装の8分割Coonsパッチを変えず、各出力画素に対応する
入力画像座標 `(source_x, source_y)` を `RG32Float` として保持する。
10×10区画のLUTは3200×1800×8 bytes（約43.9 MiB）。区画終了ごとに同じGPUバッファを再利用する。
入力テクスチャ、LUT、出力RGBAテクスチャを合わせたGPU側主要領域は、実装依存のアラインメントを除き
概ね100～130 MiBを見込む。境界曲線はhorizontal 21×161点、vertical 21×161点、交点441点を固定IDで渡し、
shader側で基準と同じCoons式と各サブパッチ内補間を評価する。

## 停止理由

検証に利用できるブラウザでは `navigator.gpu` が存在せず、WebGPU実行ができなかった。
さらにwarpは全体の0.9%であり、WebGPU化しても現在の主要ボトルネック（横追跡・縦交点算出）は改善しない。
未実行のGPUコードで精度・速度を主張できないため、指示どおり既存画面へ統合せず停止した。
