## 1. 概要

先生・運営者が、道場運営に必要なQRを先生メンテ画面から発行する。

対象は以下の5種類とする。

- 会員カード
- 月謝
- 都度支払い
- 道場
- 先生

QR自体は既存のURLクエリパラメータ仕様を維持する。

QRは機械向けデータ、
QR外側のHTMLシートは人間向けの識別・説明・デザインを担当する。

## 2. 目的

現在Google Sheet等で行っているQR準備作業を、
先生メンテ画面から実行できるようにする。

これによりリリース前のQR準備、再発行、印刷を
道場システム内で完結させる。

## 3. 前提条件

- [ ] 会員マスタが登録済
- [ ] 先生マスタが登録済
- [ ] 道場情報が登録済
- [ ] 料金プランが登録済
- [ ] 既存QR読取画面が利用可能
- [ ] QR生成APIへアクセス可能

## 4. 登場人物

| 区分 | ID | 説明 |
|---|---|---|
| 先生 | teacher_id | QRを発行する運営者 |
| 会員 | member_id | 会員カード、支払いQRの対象 |
| 道場 | location_id | 道場QRの対象 |
| システム |  | QR URL生成、画像生成、HTML表示を行う |

## 5. QR種別

| 種別 | QRデータ | HTML上の主要表示 |
|---|---|---|
| 会員カード | member_id | 会員カード、氏名、会員ID、QR |
| 月謝 | member_id + plan_id | 月謝、氏名、会員ID、料金プラン名、QR |
| 都度支払い | member_id + plan_id | 都度支払い、氏名、会員ID、料金プラン名、QR |
| 道場 | location_id | 道場、道場名、道場ID、QR |
| 先生 | teacher_id | 先生、先生名、先生ID、QR |

月謝／都度支払いの業務上の違いは、
QR専用フィールドを新設せず `plan_id` により表現する。

## 6. デザイン原則

- QR本体は既存仕様を維持する。
- QR種別の識別は外側のHTMLシートで行う。
- 既存の `00_画面＆QR` の色・用途の考え方を継承する。
- QR種別ごとにHTMLテンプレートを1対1で持つ。
- QR、タイトル、ID等の共通表示部品は共有可能とする。
- URL文字列は通常表示しない。必要ならデバッグ用途で確認可能とする。

## 7. シナリオ

### Step01 QR発行画面を開く

先生:
先生メンテ画面からQR発行を選択する。

システム:
発行可能な5種類のQRを表示する。

期待結果:
先生が用途からQR種別を選択できる。

### Step02 対象を選択する

先生:
QR種別に応じて会員、プラン、道場、先生を選択する。

システム:
必要なIDと表示情報を取得する。

期待結果:
QR生成に必要な値が揃う。

### Step03 QRを生成する

システム:
既存URLクエリ形式で対象URLを生成し、
QR画像URLを生成する。

期待結果:
既存読取画面と互換性のあるQRが生成される。

### Step04 HTMLシートを表示する

システム:
QR種別に対応するHTMLテンプレートへ
QR、名称、ID、補助情報を埋め込む。

期待結果:
人が用途を識別可能なQRシートが表示される。

### Step05 印刷・再発行する

先生:
ブラウザ印刷を行う。
必要な場合は同一条件で再度生成する。

システム:
同じIDから同じ用途のQRを再生成する。

期待結果:
専用の発行履歴を持たなくても再発行できる。

### Step06 実機で読み取る

先生:
印刷物または画面上のQRをスマートフォンで読み取る。

期待結果:
想定された画面へ到達し、対象IDが正しく認識される。
