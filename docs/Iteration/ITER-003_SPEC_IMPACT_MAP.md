# ITER-003 仕様整合 Impact Map

対象: 料金プラン確定タイミングと会費回収照合

## 基準仕様

`出席 → 月額/都度確定 → 回収予定総額 → 回収 → 現金/PayPay実績 → 照合`

## 影響分類

| 成果物 | 判定 | 対応 |
|---|---|---|
| STORY-901 通常一日運営 | 修正 | 上位の実運用Storyとして業務順序を明文化 |
| STORY-001 通常出席 | 修正 | 出席時の04確認・初回登録を追加 |
| STORY-002 未払いPayPay | 修正 | 料金プラン決定責務を外し既存請求の支払いへ |
| STORY-003 現金受付 | 修正 | 支払方法は回収時確定と明記 |
| STORY-P001 決済エビデンス | 維持 | 未払い請求に対する支払方法選択は整合 |
| STORY-C001 現金受付 | 維持 | 既存請求への現金入金として整合 |
| STORY-QR-001 | 修正 | 通常運用5種→3種。月額/都度QRは廃止候補 |
| ARCH-004 | 維持＋後続確認 | Attendance/Billing連携点の追記余地あり |
| ARCH-006 | 維持＋後続確認 | Business Process自体は維持、連携順序はMain Storyで表現 |
| ARCH-007 | 維持 | Main Storyで業務を書く原則が今回の修正方針に合致 |
| ARCH-018 | 新規 | 業務情報の確定タイミング原則を定義 |
| TASK-FEE-020 | 修正 | 受付登録額ベースの予定値を廃止し、出席由来の予定総額へ |
| TASK-QR-001〜005 | 修正 | 通常運用QRを3種へ |
| TASK-DEV-011 | 後続修正 | Runnerを新しい業務順序へ並べ替える |
| PayPay会員画面 | 後続修正 | 04登録を主責務にせず既存請求支払いへ |
| 先生会費受付UI | 後続修正 | 予定総額と実績内訳/未回収額へ |
| 旧回収整合UI | 廃止候補 | 確認現金/PayPay手入力・コピーUIを整理 |
| payment-monthly/onetime QR資産 | 廃止候補 | 参照確認後に物理削除 |
| 審査費QR | 維持/別判断 | 通常会費とは別の追加請求イベント |

## 実装へ降ろす順序

1. 出席登録時の04確認・初回登録
2. 回収予定総額の取得・表示
3. 旧回収整合UIの置換
4. PayPay会員画面の責務整理
5. QR発行UI/HTMLの整理
6. Runner更新
7. E2E → ドメイン動作確認

変更は一周回すことを優先し、既存の冪等処理・料金計算・Payment記録処理は可能な限り再利用する。
