# 先生向け操作仕様

作成日: 2026-10-19  
対象起点: `web/qr/teacher_home.html`  
位置付け: 先生向け操作マニュアル作成のための現行実装調査

## 1. 本書の読み方

本書は、ソースコードと既存Architecture文書から確認できる現在の画面・操作契約を整理したものである。将来構想は現行機能として扱わない。

機能状態は次のように表記する。

| 状態 | 意味 |
|---|---|
| 実装済み（Firebase/GAS） | Firebase版とGAS版の両方に対応する |
| Firebase限定 | Firebase版のみ利用できる |
| GAS限定 | GAS版のみ利用できる。Firebase Hostingから開いても正常動作は保証されない |
| 画面試作 | 架空データによる操作イメージ。業務データを保存しない |
| 準備中 | 遷移先または業務処理が未実装 |

## 2. ログインと共通動作

### 2.1 入口から先生ホームまで

```text
入口 index.html
  ├─ 先生QRを読み取る
  ├─ URLに teacher_id がある場合は自動適用
  └─ 既存の先生セッションで「続ける」
          ↓
先生ホーム teacher_home.html
```

入口で先生QRから `teacher_id` を取得すると、ブラウザの `sessionStorage` に仮想先生セッションを保存し、先生ホームへ遷移する。URLに `location_id` がある場合は道場Contextとして保持する。

仮想セッションに保持する主な情報は次のとおり。

- 役割: `TEACHER`
- 先生ID: `teacher_id`
- 業務Context: `location_id`、`billing_block_id`、`teacher_id`

仮想セッションは画面遷移を便利にするための仕組みであり、サーバーの本人認証・認可ではない。Firebase版で保護されたAPIを使用する画面では、別途Googleログインとサーバー側の管理者権限確認が必要になる。

### 2.2 先生ホーム

画面にはログイン中の先生ID、システムContextの応答時間、先生メニュー、操作ログを表示する。

操作:

- 各業務画面を開く。
- 「ログアウト」で仮想セッションを破棄し、入口へ戻る。
- 「入口へ戻る」で入口画面へ移動する。これはログアウト操作ではない。

エラー時:

- SystemContext取得失敗時は「GAS応答: TIMEOUT」相当の表示と操作ログを残す。
- 先生セッションがない場合は「未ログイン」のままとなる。

## 4. 会費受付

対象: `web/qr/payment_teacher.html`  
状態: 実装済み（Firebase/GAS）。ただし保存方式が異なる。

### 4.1 主な操作

- 道場・先生・課金枠の受付Scopeを確認する。
- QRカメラを開始・停止する。
- 会員QRを読み取り、会員名・請求グループ・未払い額を表示する。
- 現金を受領する。
- 本日の現金・PayPay・合計・件数を再取得する。
- 出席人数と未回収予定額、要確認情報を表示する。
- PayPayのCONFIRMED証跡を選択し、入金へ反映する。
- POSTED済みのPayPay証跡を確認する。
- 画面をクリアする。

### 4.2 必要な入力・前提

- `teacher_id`
- `location_id`
- `billing_block_id`
- SystemContextの業務日
- 会員QRの `member_id`
- 旧QR等では任意の `plan_id`
- Firebase版ではFirebase管理者としてのGoogleログイン

受付Scopeは、URL、同一先生の仮想セッション、画面で読み取ったQRの情報から設定される。課金枠を自動確定できない場合は、URL・セッション・QRによる指定が必要になる。

### 4.3 保存・更新

Firebase版:

- 現金受領は会員1件ごとに `payment_cash_accept` で即時確定する。
- 請求状態、入金ログ、決済証跡、冪等性記録をFirestoreトランザクションで更新する。
- PayPay反映は選択したCONFIRMED証跡を `payment_paypay_post_selected` でPOSTEDへ進め、入金へ反映する。
- 処理後に会員情報と `payment_screen_read` を再取得する。

GAS版:

- 現金受付を画面内リストへ一時追加し、「集金完了」でまとめてGASへ送信する。
- 未送信リストは個別削除できる。
- PayPay証跡の一覧取得と選択反映はGASの既存処理を使用する。

### 4.4 完了表示

- Firebase現金: 操作ログに会員IDと受領額を表示し、最新の会員情報・受付集計へ更新する。
- Firebase PayPay: 「PayPay決済更新完了」と反映件数を操作ログへ表示する。
- GAS現金: POST要求完了後、登録済み集計と一覧を再取得する。
- 集計欄に現金、PayPay、合計、入金件数、未回収予定額、出席人数を表示する。

### 4.5 エラー時

- Firebase未認証は管理者ログインを求める。
- 401、403、通信失敗、受付Scope不足、業務日不足を画面上と操作ログへ表示する。
- 未払い0円、請求グループ不明、請求未作成、月次選択未登録、plan不一致の場合は受付を停止する。
- 同一請求グループの重複受付を停止する。
- 二重クリック中は再送を抑止する。
- 通信結果が不明な場合は失敗と断定せず、同じ `request_id` を維持して再試行可能な状態にする。

## 5. 会員管理

対象: `web/qr/member_management.html`  
状態: Firebase限定。GAS版では「会員管理はFirebase版で利用できます」と表示して停止する。

### 5.1 主な操作

- 会員一覧を表示・再読込する。
- 会員ID、氏名、ふりがなで絞り込む。
- 会員を新規登録する。
- 既存会員を編集する。
- 1～5人の支払いグループを編成する。
- 会員IDを指定して退会手続きを行う。

### 5.2 会員登録・編集の入力

- 会員ID（新規時のみ編集可能、必須）
- 氏名（必須）
- ふりがな
- 会員区分（必須）
- 状態
- 入会日（必須）
- 退会日
- 休会開始月・終了月
- 生年月日
- 保険区分
- メール
- 電話
- 現在級段位
- 備考

新規会員には次の未使用 `BGxxx` が支払いグループ初期値として設定される。

### 5.3 支払いグループ編成の入力

- 編成先: 新しいグループ、または既存 `BGxxx`
- グループへ入れる会員
- グループ共通の会費タイプ
- 人数・会員区分・選択ルールに対応する料金プラン候補

料金プラン候補は初期表示用であり、この画面では月次料金プランを確定しない。確定は既存の月次会費管理の責務である。

### 5.4 退会の入力

- 退会対象の会員ID
- 退会日
- 確認ダイアログへの同意

### 5.5 保存・更新

- `members` の会員情報を新規作成または更新する。
- 支払いグループ編成では、対象会員の `billing_group_id` を更新する。
- 退会処理では会員状態と退会日を更新する。
- 過去の請求・入金履歴は変更しない。
- グループ編成だけでは料金プランや請求を作成しない。

### 5.6 完了表示・エラー

完了時:

- 「会員情報を保存しました。」
- 「支払いグループを保存しました。料金プランは月次会費管理で確定してください。」
- 「退会手続きを保存しました。」
- 保存後に一覧を再取得する。

エラー時:

- Firebase管理者ログインがない場合はログインを要求する。
- APIエラーコードまたはHTTPステータスをメッセージ欄へ表示する。
- 退会対象未入力、該当なし、ID重複を画面上で拒否する。
- 6人以上、会費タイプ不一致、人数対応プラン不一致などは保存APIで拒否する。

## 6. 審査管理

対象: `web/qr/examination/index.html`  
状態: **画面試作・保存なし**。

現在できるのは、架空データを使った次の操作だけである。

- 級審査・段審査の切替
- 審査予定日による絞り込み
- 受験登録済み・候補者・その他による絞り込み
- 会員別の稽古回数、稽古日数、経過年数、到達見込み、目標審査日の表示
- 「候補者に設定」「受験登録」の疑似操作

疑似操作は画面内のJavaScriptデータだけを変更し、再読込すると元へ戻る。実会員、審査予定、審査結果、Firestore、GASへは保存しない。資格判定・予測計算も実行しない。

ARCH-024に定義された審査日程、近日到達見込み、結果文章・結果日、履歴、保留・確定処理は将来要件であり、現行画面には未実装である。

## 7. 本日の出席

対象: `web/qr/attendanceCheck.html`  
状態: 実装済み（Firebase/GAS）。Firebase版はFirebase管理者ログインを使用する。

### 7.1 主な操作

- 道場・課金枠・先生を設定する。
- 当日の課金枠候補から対象を選択する。
- 本日の登録済み出席者を表示・更新する。
- 出席者を登録順、級・段順、審査が近い順に並べ替える。
- 会員QRを読み取り、登録対象へ追加する。
- 会員ごとに出席する稽古枠を選択・解除する。
- 現在級段位を選択する。
- Firebase版では、未確定の場合に会費タイプを選択する。
- 選択した出席をまとめて同期する。
- 登録候補一覧をクリアする。

### 7.2 必要な入力

- 先生ID
- 道場ID
- 課金枠ID
- SystemContextの稽古日
- 会員ID
- 稽古枠
- 現在級段位
- Firebase版で必要な場合は料金プラン

### 7.3 保存・更新

- 会員・日付・道場・課金枠に対する選択済み稽古枠を、画面状態と同期する。
- 追加された枠を出席登録し、解除された枠は取消履歴を残す。
- 画面で変更した現在級段位を会員情報へ反映する。
- Firebase版では必要に応じて月次選択・請求を既存業務処理で確定する。
- 受付主体、道場、課金枠、セッションID等を保存する。

### 7.4 完了表示・エラー

完了時:

- Firebase版は各会員の保存状態を再取得し、送信内容との一致を確認する。
- 本日の出席者一覧を再取得する。
- GAS版はPOST receiptを待ち、完了後に保存状態を再取得する。

エラー時:

- 先生・道場・課金枠不足、会員なし、現在級段位未選択、保存済み状態未取得を送信前に拒否する。
- Firebase版で会費タイプが必要なのに未選択の場合は送信しない。
- 保存結果が画面の期待状態と一致しない場合はエラーにする。
- QR・マスタ・通信・認証エラーを画面下部の操作ログに表示する。

状態: **GAS限定**。共通WebConnect契約には操作名があるが、現行Cloud Runの許可action・ハンドラには接続されていない。

### 8.1 主な操作と入力

- 道場QR・課金枠QRを読み取る。
- 主先生／副先生を選択する。
- 対象稽古枠を選択・解除する。
- 登録済み状態を読み込む。
- 当月の先生別「主・副・合計」回数を表示する。

### 8.2 保存・完了・エラー

- `16_先生出席ログ`へ、稽古日・稽古枠・先生・担当区分を同期保存する。
- 「先生出席を登録しました。」表示後、登録状態と月次集計を再取得する。
- 曜日不一致、先生・道場・課金枠不足、SystemContext取得失敗、通信タイムアウトをエラー表示する。
- 先生の給金対象、単価、金額は判定・保存しない。

## 9. 会費状況

対象: `web/qr/payment_status.html`  
状態: **GAS限定・参照専用**。`teacher_payment_status`はCloud Runに接続されていない。

入力:

- 入金日の開始日
- 入金日の終了日
- 会員別状況の対象月

表示:

- 現金・PayPay・合計・入金件数
- 請求グループごとの請求額・入金額・未払い額・状態
- 稽古課金回数と請求概要
- 指定期間の入金明細

保存・更新は行わない。「表示を更新」でGASから再取得する。対象データがない場合は空状態を表示し、通信・業務エラーは集計条件欄のメッセージに表示する。

## 10. 決済コード確認

対象: `web/qr/paymentEvidence.html`  
状態: **画面試作**。

画面上は会員IDとPayPay決済コードを入力し「登録（仮）」を押せるが、表示を「仮登録画面です。GAS連携は次ステップで実装します。」へ変更するだけで、保存・確認・入金反映は行わない。

実際のPayPay確認・入金反映は、現在は「会費受付」画面のCONFIRMED／POSTED一覧から行う。

## 11. QR生成

対象: `web/qr/qr_generator.html`  
状態: 実装済み（Firebase/GAS）。Firebase版はFirebase管理者ログイン、GAS版は先生仮想セッションを前提とする。

### 11.1 作成できるQR

| 種類 | 必要な選択 |
|---|---|
| 会員カード | 会員 |
| 月謝 | 会員、月謝プラン |
| 都度支払い | 会員、都度プラン |
| 道場 | 道場 |
| 先生＋道場 | 先生、道場 |

会員区分とプラン選択ルールにより選択可能な料金プランを絞り込む。

### 11.2 操作

- QR種別と発行対象を選択する。
- 選択内容を確認してプレビュー画面へ移動する。
- QRをB5印刷リストへ追加する。
- 同一QRを複数回追加する。
- 印刷リストから個別削除または全件クリアする。
- 登録順を維持し、8枚ごとにB5横向きページへ配置してブラウザ印刷を開く。

### 11.3 保存・完了・エラー

- 印刷リストはページ内メモリだけに保持し、FirestoreやGASへ保存しない。
- 生成対象のマスタは `qr_generator_options` から読み取る。
- 選択不足、対象プランなし、認証不足、通信失敗を画面メッセージと診断ログへ表示する。
- 「B5 PDF／印刷」はPDFファイルをサーバー生成する機能ではなく、印刷レイアウトを描画してブラウザの印刷ダイアログを開く。

## 13. Firebase版とGAS版の相違一覧

| 機能 | Firebase版 | GAS版 |
|---|---|---|
| 仮想先生ログイン | 利用 | 利用 |
| サーバー認証 | 対応画面ではFirebase ID Tokenと管理者権限 | 仮想セッション／既存GAS経路。Firebaseと同じ認証方式ではない |
| 会費受付 | 現金1件即時確定、PayPay選択反映 | 現金を画面内で蓄積後に一括送信、PayPay選択反映 |
| 会員管理 | 実装済み | 利用不可 |
| 本日の出席 | Bearer付きWebConnect、保存後照合 | JSONP読取＋フォームPOST＋receipt確認 |
| 先生出席 | 未接続 | 実装済み |
| 会費状況 | 未接続 | 実装済み |
| QR生成 | 管理者認証付き読取 | 先生仮想セッション＋JSONP読取 |
| 審査管理 | 画面試作のみ | 画面試作のみ |
| 決済コード確認 | 画面試作のみ | 画面試作のみ |

Firebase版では、画面に表示された `teacher_id` やQR内容だけを認可根拠にせず、対応済みAPIでFirebase ID Tokenと管理者権限をサーバー側確認する。

## 14. 操作マニュアル作成時の注意

- 「審査管理」「決済コード確認」「月次処理」「お知らせ」を実運用機能として案内しない。
- Firebase版の先生出席・会費状況を操作可能と案内しない。
- 会員管理の支払いグループ候補を、月次プラン確定操作として案内しない。
- QR生成の印刷リストはブラウザ内だけであり、再読込後の復元を案内しない。
- 会費受付のFirebase版とGAS版では現金受付の確定タイミングが異なるため、同一手順として記載しない。
- 仮想先生ログインとFirebase管理者ログインを同じ認証として説明しない。
