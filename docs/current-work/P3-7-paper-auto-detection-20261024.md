# P3-7 用紙自動検出の追加評価と段階的統合

実施日: 2026-10-24  
範囲: 独立PoC、PC評価、iPhone検証準備、統合差分設計。既存画面への組込み・配信なし。

## 結論

用紙外周の自動検出から既存P3-6の400カード生成まで接続できた。追加された横撮影サンプルでは、画像ファイル上の90度回転を正規化したうえで、21×21罫線、400カード、既知記入セル27/27を確認した。最初の縦構図サンプルは20/27のため、実写1件の成功だけで一般化せず、統合前に横撮影条件を追加評価する。

## 自動用紙検出アルゴリズム

1. `createImageBitmap(..., imageOrientation: from-image)`で向きを反映。
2. 最大辺720pxへ縮小し、RGBの最小値を主体とする白色度画像を作成。
3. Otsu閾値と小型形態処理で明るく低彩度の領域を抽出。
4. 連結領域を面積、位置、横長比率、画像端接触で評価。
5. 上下左右の境界点をロバスト直線近似。
6. 用紙内外の符号付き色差を使って4辺を局所吸着。
7. 交点をTL/TR/BR/BLとして既存P3-6の`paperCorners`へ渡す。

用紙四隅と20×20格子四隅は別データであり、混同していない。

## 実写評価

使用画像: 2880×3840のiPhone撮影画像。木目机、斜め撮影、専用台紙なし、用紙四隅は全て画面内。

| 項目 | 結果 |
|---|---:|
| 用紙検出 | 170 ms |
| 信頼度 | 0.947 |
| 四隅平均誤差 | 25.09 px |
| 四隅最大誤差 | 49.24 px |
| 400カード | 成功 |
| P3-6全体 | 110.032秒 |
| WASMヒープ | 169.50 MiB |
| 最終試行 | 20/27 |
| 最良試行 | 26/27 |

外周誤差が小さく見えても、後段の格子正面化とセル判定へ影響した。輪郭信頼度だけでは合格にできない。

### 追加横撮影サンプル

使用画像: 2880×3840 JPEG。撮影時は横構図、ファイル座標では用紙の長辺が縦。木目机と黒い下敷き、用紙周囲の余白は少なめ、四隅は全て画面内。

| 項目 | 結果 |
|---|---:|
| 用紙検出 | 204 ms |
| 用紙検出信頼度 | 0.762 |
| 向き補正 | -90度 |
| 推定罫線 | 縦21本・横21本 |
| 格子信頼度 | 0.747 |
| 400カード | 成功 |
| 既知記入セル | 27/27、見落とし0 |
| 全処理 | 384.720秒 |
| WASMヒープ | 167.62 MiB |
| 候補／要確認／空白 | 68／31／301 |

用紙外周は正しく検出された。検出四隅を画像座標順のまま横長出力へ割り当てると90度誤るため、物理的な長短辺を判定して四隅順を回転させた。この正規化は用紙検出後・射影変換前だけに適用し、既存P3-6の精密補正は変更していない。

## 背景条件

- 木目机: 実写評価済み。外周検出・400カード成功、27/27未達。
- 濃色無地、明色、白背景、強い影: 元画像不足で未検証。
- 横撮影: 追加実写1枚で成功。今後の標準条件。
- 周囲背景が少ない構図: 追加実写1枚で成功。ただし黒い下敷きとの境界が明瞭な条件。
- 四隅切れ: 検出対象外。撮り直しを案内する。

合成画像は実写合格件数へ含めていない。

## P3-6回帰

P3-6のWorker、21×21罫線追跡、441交点、Coons補正、400カード、セル判定は変更していない。自動検出した用紙四隅だけを入力した。追加横撮影サンプルでは、WASMヒープ167.62 MiBで27/27を維持した。一方、処理時間は384.720秒であり、P3-6基準約109秒より大幅に長い。

## 手動補正が必要な条件

- 自動四隅のいずれかが画像端へ接触する。
- 用紙候補の面積・横長比・色差が基準外。
- 後段の20×20格子信頼度または21×21本数が不足。
- 白い机、強い影、用紙と背景が連結して見える条件。
- 四隅が画像外の場合は手動補正ではなく撮り直し。

## 既存画面への統合差分案

- `paper_attendance_review.html`: 「用紙を自動検出中」「四隅確認」「撮り直し」状態を追加。
- `paper_attendance_review.js`: 画像選択後に用紙検出を実行し、合格時だけ既存Workerへ`paperCorners`を渡す。失敗時は既存手動ハンドルを表示。
- 新規の小型用紙検出モジュール: DOM、API、業務処理から独立。
- 既存Worker/Python: 契約変更不要。

Gemini、会員照合、差分登録、通常出席、会費、認証、Cloud Runは変更不要。

## 残課題と推奨作業

横撮影の実画像を通常木目机でさらに2～3枚取得し、黒い下敷きなし、角度、影、周囲余白を変えて再評価する。合格条件は、四隅が正しいこと、21×21本、400カード、27/27、見落とし0。今回の候補68件は用紙検出の合否とは分離し、原因確認前にセル閾値を変更しない。実機Safariでの処理時間と安定性も未確認である。

commit、push、deploy、Firestore、GAS、Cloud Run、既存画面の変更は実施していない。
