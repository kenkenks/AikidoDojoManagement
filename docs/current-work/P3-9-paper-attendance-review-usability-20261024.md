# P3-9 紙出席記録・確認画面の操作性改善

実施日: 2026-10-24  
範囲: ローカル修正と検証のみ。commit、push、deploy、Firestore書込みは実施していない。

## 結論

登録済み2Hに対し紙の記録・修正後の合計が3Hの場合、「今回追加する時間 ＋1H」と「登録後の合計 3H」を分けて表示するようにした。登録ボタンは準備完了後に「追加1Hを登録」のように表示する。追加0Hの場合は、登録対象がない理由とAPIを呼び出さないことを明示する。

「指定セル以降を空白」は、画面内部の水平方向配列順ではなく、紙面の「各列を下から上、次の列へ」という記入順で処理する。`??/??`を含む記入済みセルも位置に基づいて空白化する。

## 原因

- 従来の `confirmTrailingEmptyCells()` は、セルのrow-major配列の `startIndex`以降を水平方向に走査していた。紙面の記入順と一致していなかった。
- 同関数は既に空白のセルだけを「確認済み」にし、記入済みや `??/??` は空白化しなかった。
- 差分計算は `max(紙の合計-登録済み, 0)` で正しかったが、表示名が「手修正後時間」「追加予定時間」だけで、合計値と今回追加値の違いが利用者に伝わりにくかった。
- 追加0Hの場合は実行ボタンがdisabledになるだけで、一見無反応に見える状態があった。

## 表示・操作の変更

### 日付別差分表

表示列を次の7項目に整理した。

1. 稽古日
2. 登録済み
3. AI読取（参考）
4. 紙の記録・修正後の合計
5. 今回追加する時間
6. 登録後の合計
7. 状態・理由

`afterMinutes = confirmedMinutes + addMinutes` を表示用に追加した。登録レコードの生成と送信ロジックは変えていない。

### ボタンと0H案内

- 準備済みレコードの合計が60分なら「追加1Hを登録」と表示する。
- 追加がない場合は「追加対象なし」と表示し、ボタンをdisabledのままにする。
- 差分表と登録プレビューの両方で、登録済み時間と同じか、登録済み時間の方が多いため追加0Hであると説明する。
- 0Hでは従来どおり登録APIを呼び出さない。

### 指定セル以降の空白化

- 紙面順番を `(column - 1) * rowCount + (rowCount - row)` の0始まり値で定義した。
- 指定セル以降の各セルを `raw=""`, `date=""`, `status="empty"`, `confirmed=true`, `manual=true` にする。
- 日付解析結果に依存せず、`??/??` でも位置によって空白化できる。
- 確認ダイアログに起点と対象セル数を表示し、Firestoreの登録済み出席は変更しないことを明示する。
- 操作後は既存の `remap()` から差分表を再計算する。
