# ARCH-VIRTUAL-LOGIN-001 仮想ログイン

## 目的

先生・会員QRから取得した操作主体を、同一タブ内の画面遷移中に保持する。

## Reality

- 保存先はブラウザの `sessionStorage` とする。
- 先生は `TEACHER + teacher_id`、会員は `MEMBER + member_id` を保持する。
- タブを閉じた場合、または明示ログアウト時に状態を破棄する。
- タイムアウト判定は今回実装しない。ただし将来追加用に `logged_in_at` と `last_accessed_at` を保持する。
- 入口で人物QRを読んだ場合だけログイン主体を切り替える。
- 先生画面で読み取る会員QRは業務対象であり、先生のログイン主体を会員へ切り替えない。
- 道場・課金枠は業務コンテキストであり、ログイン主体には含めない。
- 業務コンテキストはログインセッション内の `context` に保持する。
- 現時点の保持対象は `location_id`、`teacher_id`、`billing_block_id` とする。
- 保持対象外の項目は `setContext()` で拒否し、ログイン主体を業務画面から上書きさせない。
- ログイン主体を切り替えた場合、旧主体の業務コンテキストは引き継がない。
- JSON破損・必須項目欠落など不正な保存値は自動破棄する。

## セキュリティ上の位置付け

これは画面操作を便利にする仮想ログインであり、本人認証・認可ではない。QRの所持確認、署名、サーバーセッション等は将来の本認証で扱う。


## Runner

`work/verify-virtual-session.mjs` をコアランナーとして使用し、次を画面非依存で確認する。

- 先生・会員セッションの生成と切替
- 業務コンテキストの設定・解除
- 保持対象外項目の拒否
- 破損セッションの自動破棄
- ログアウト

フレームワークの不具合調査と仕様追加は、まずこのランナーで再現・固定してから画面へ展開する。

## 会費受付画面への適用

`payment_teacher.html` は次の優先順位で受付スコープを決定する。

1. URLで明示された `location_id`、`teacher_id`、`billing_block_id`
2. 同一先生セッションの業務コンテキスト
3. 画面内で読み取ったQR

URLで別の先生を明示した場合、旧先生セッションの業務コンテキストは補完に使用しない。
道場・課金枠・先生QRで受付スコープが確定または変更された場合、現在画面に表示されている値をセッションへ保存する。
セッションが存在しない場合は従来どおりURL・QRのみで動作する。

`work/verify-payment-session-context.mjs` で、URL優先、同一先生Session補完、別先生への旧Context非継承、QR後のContext保存を確認する。

## Story Runner

`work/runner-story-session-001.mjs` は、Session Frameworkを利用する一連の画面操作を再現する。

1. 先生 `T001` で仮想ログインする。
2. Attendanceで道場・課金枠を確定し、Session Contextへ保存する。
3. PaymentをURL指定なしで開き、同一先生のContextを継承する。
4. URLで別先生 `T002` を指定し、旧先生のContextが流用されないことを確認する。
5. LogoutでSessionを破棄する。

Story Runnerは、各画面の実装関数を読み出して実行する。Sessionコアだけでなく、画面との接続が壊れた場合も検出対象とする。
