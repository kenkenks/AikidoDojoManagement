# ARCH-VIRTUAL-LOGIN-001 仮想ログイン

## 目的

先生・会員QRから取得した操作主体を、同一タブ内の画面遷移中に保持する。

## Reality

- 保存先はブラウザの `sessionStorage` とする。
- 先生は `TEACHER + teacher_id`、会員は `MEMBER + member_id` を保持する。
- タブを閉じた場合、または明示ログアウト時に状態を破棄する。
- タイムアウト判定は今回実装しない。ただし将来追加用に `logged_in_at` と `last_accessed_at` を保持する。
- 入口で人物QRを読んだ場合だけログイン主体を切り替える。
- 先生画面で読み取る会員QRは業務対象であり、先生のログイン主体を会員へ切り替えない。
- 道場・課金枠は業務コンテキストであり、ログイン主体には含めない。
- 業務コンテキストはログインセッション内の `context` に保持する。
- 現時点の保持対象は `location_id`、`teacher_id`、`billing_block_id` とする。
- 保持対象外の項目は `setContext()` で拒否し、ログイン主体を業務画面から上書きさせない。
- ログイン主体を切り替えた場合、旧主体の業務コンテキストは引き継がない。
- JSON破損・必須項目欠落など不正な保存値は自動破棄する。

## セキュリティ上の位置付け

これは画面操作を便利にする仮想ログインであり、本人認証・認可ではない。QRの所持確認、署名、サーバーセッション等は将来の本認証で扱う。


## Runner

`work/verify-virtual-session.mjs` をコアランナーとして使用し、次を画面非依存で確認する。

- 先生・会員セッションの生成と切替
- 業務コンテキストの設定・解除
- 保持対象外項目の拒否
- 破損セッションの自動破棄
- ログアウト

フレームワークの不具合調査と仕様追加は、まずこのランナーで再現・固定してから画面へ展開する。

## Attendance画面への適用ルール

- 画面起動時は URL パラメータを最優先とする。
- URLに指定されていない `location_id`、`billing_block_id`、`teacher_id` は、同一タブのSession Contextから補完する。
- QR読取、画面選択、現在時刻による課金枠自動確定の結果はSession Contextへ保存する。
- Sessionが存在しない場合は従来どおりURL・QRのみで動作し、Context保存は行わない。
- 同一先生の再読取ではログインSessionを作り直さず、保持中の道場・課金枠を維持する。
- 別の先生へ切り替えた場合は新しいログイン主体としてSessionを作り直し、その時点の画面Contextだけを明示的に保存する。
- `work/verify-attendance-session-context.mjs` で、URL優先・Session補完・確定値保存の接続を確認する。
