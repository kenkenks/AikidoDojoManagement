# ARCH-024 審査・昇級昇段管理アーキテクチャ

Version: 0.5
Date: 2026-10-19
Status: PROPOSED（業務方針合意・実装前）
Scope: 審査レギュレーション／審査予定／審査結果／昇級昇段／画面連携

## 1. 目的と原則

審査資格の進捗表示だけでなく、先生が審査予定を登録し、受験者を選定し、合否と正式な起算日を確定し、次回審査の進捗へつなぐ一連の業務を実現する。

審査管理の対象は、先生を含む道場所属の全会員とする。先生も稽古参加時は会員として会員カードで出席登録し、先生用カードは管理業務の操作に使用する。先生専用の会費タイプは出席実績および審査資格の判定には影響させない。

- 審査資格の自動判定は、合格・昇級・昇段の自動確定を意味しない。
- 先生の明示的な確定操作を、級段位更新の唯一の通常入口とする。
- 出席履歴は事実記録として保持し、審査のために移動・書換え・二重計上しない。
- 成人／少年、級／段は共通の判定・イベント処理を利用し、適用する基準と日付で差を吸収する。
- GAS／Firestore、会員画面／先生出席確認画面／審査管理画面で判定ロジックを重複させない。
- 既存DAO・業務境界を尊重し、用途別APIや並行実装経路を無制限に増やさない。

関連: `ARCH-009`（データアクセス）、`ARCH-018`（業務情報の確定タイミング）、`ARCH-022`（共同開発）。

## 2. 業務の状態遷移

以下は審査予定から結果確定までの業務フローである。候補の予測と正式な受験登録は区別する。

```text
審査予定作成／変更
  → 対象者候補の資格判定（現時点の実績と予定日見込みを区別）
  → 先生が受験者を登録
  → 審査実施（実施日を記録し、審査レコードを保留状態で管理）
  → 結果通知待ち（出席記録は通常どおり蓄積）
  ├─ 合格通知：正式起算日を確認 → 先生が結果を確定して保留解除 → 級段位・起算日を更新
  └─ 不合格通知：先生が結果を確定して保留解除 → 級段位・起算日は維持
  → 次回審査の進捗を再計算
```

- 予定日・実施日・結果確定日時・正式合格日・進捗起算日は異なる概念として保持する。
- 予定変更、受験取消、結果待ち、合否確定、確定後の訂正を扱う。確定後の訂正は監査履歴を残す専用操作とする。
- 審査資格を満たすことと、先生が受験予定者に選ぶことは別の状態である。
- 結果待ちの進捗は「判定保留」として扱い、未確定の級段位に対する進捗を確定値として提示しない。
- 保留解除は表示状態だけの変更ではない。結果、会員の級段位、起算日、級段位履歴および進捗を整合させる確定処理とする。
- 審査日程、審査対象者、進捗、結果および履歴を一連の管理対象とする。資格到達による受験者登録や結果確定は自動実行しない。

## 3. 級・段を統一する日付モデル

| 日付 | 用途 | 昇級の既定 | 昇段の既定 |
|---|---|---|---|
| 審査予定日 | 受験計画と見込み判定 | 予定日 | 予定日 |
| 審査実施日 | 実際に審査を受けた日 | 実施日 | 実施日 |
| スタック開始日 | 審査後の稽古実績の帰属を保留する境界 | 審査実施日の翌日から（審査当日は旧級段位） | 原則、正式合格日（通知後に確定） |
| 正式合格日 | 合格の根拠となる日 | 原則、審査実施日 | 合気会通知の正式合格日 |
| 新級段位の起算日 | 次回審査進捗の起点 | 原則、審査実施日（当日の出席は旧級段位） | 正式合格日 |
| 結果確定日時 | 先生がシステム上で確定した時刻 | 確定操作時 | 確定操作時 |

- 級では審査後の稽古実績を結果待ちとして扱い、合格なら新しい級、不合格なら従来の級に帰属させる。
- 段では原則スタック運用を行わず、正式合格日を境界として再集計する。共通エンジンに日付設定を渡して吸収する。
- 「スタック」は別の出席コピーではなく、審査イベントの状態と日付に基づく集計上の保留を意味する。
- 審査当日の稽古実績は旧級段位へ帰属させる（第11章の運用方針）。
- 先生は例外時に日付を調整できる。ただし変更理由・変更者・変更日時を記録する。

## 4. 審査レギュレーションと判定

審査資格は、稽古枠数、稽古日数、経過年数の3指標で判定する。会費計算上の課金枠数は審査判定に使用せず、請求領域に限定する。例えば同日に2稽古枠へ参加した場合、稽古枠数は2、稽古日数は1として扱う。課金枠数が1となる運用であっても審査判定には影響させない。

既存の `schema/ExaminationStandard.yml` は「必要稽古数」「必要経過年数」を持つが、「必要稽古日数」は未定義。既存の「必要稽古数」は出席した稽古枠数を意味するものとして維持し、既存値の意味を無断で変更せず、稽古日数を独立した項目として追加する。

```text
required_training_count   既存の必要稽古回数（既存運用を維持）
required_training_days    必要稽古日数（同一暦日の複数稽古枠は1日）
required_elapsed_years    必要経過年数（暦年の加算で判定）
```

- 設定された有効条件をすべて満たす場合のみ「資格あり」。級段位や道場運用に応じて使用する指標の組合せを審査基準で定める。未設定条件は判定から除外するが、設定漏れとゼロ条件を混同しない。
- 稽古回数は、対象級段位の起算日以降に出席した有効な稽古枠の数とする。課金枠への集約結果を参照しない。
- 稽古日数は原則、対象級段位の起算日以降の異なる出席日付の数とする。既存の繰越稽古数の挙動は今回の基準変更で勝手に改変しない。
- 必要経過年数は起算日から暦年で計算する（閏年を365日換算しない）。起算日が不明なら「判定保留／要確認」。
- 予定日までの将来の出席を実績として加算しない。「現在の資格判定」と「予定日までの見込み」を分離する。
- 成人と少年は共通スキーマを利用するが、基準値は独立させる。少年の基準値に成人基準を流用しない。
- 年齢要件は今回の実装範囲外。後続の拡張点として残す。
- 全体レギュレーション調整と、会員ごとの判定用実績・起算日調整を分離する。調整値は実出席記録を変更せず、理由付きで保存する。

## 5. 次回審査日予測判定

### 5.1 目的と位置付け

審査資格の実績判定とは別に、会員ごとの稽古ペースから資格到達時期を予測し、先生と会員が目標とする審査日を検討・共有できるようにする。特に段審査は年3回の機会を想定し、どの審査日を目指すかを判断する材料とする。予測は受験資格の確定や正式な受験登録を意味しない。

### 5.2 入力情報

- 会員ごとの直近3か月の実出席履歴（稽古枠数・稽古日数）。
- 現在の級段位、進捗起算日、審査基準マスタの必要稽古回数・日数・経過年数。
- 登録済みの今後の審査予定日。
- 会員が任意に設定する予測用稽古頻度の補正値。

### 5.3 稽古ペースと到達見込みの算出

- 判定日から直近3か月の出席実績を基に、会員ごとの週平均稽古枠数と週平均稽古日数を**別々に**算出する。同日に複数枠出席した場合も、稽古日数は1日とする。課金枠数は使用しない。
- 稽古回数・日数の不足量と各週平均から、今後の到達見込みを算出する。経過年数は起算日から暦年で計算する。
- 審査基準に設定された有効条件はすべてANDとして扱い、各条件を満たせる見込みの日付を審査予定日と照合する。
- 出席実績が少ない、直近3か月の出席がない、必要な起算日や基準が欠損する等、妥当な予測ができない場合は「予測困難／要確認」と表示し、根拠のない到達日を作らない。
- 予測値は見込みであり、将来の出席を確定実績として加算しない。

### 5.4 会員による予測用の補正

- 会員は、今後の稽古計画に合わせて予測用の稽古頻度を任意に補正できる。
- 実績から求めた平均値と補正後の予測用数値は区別して表示する。
- 補正値は到達予測のみに利用し、出席履歴・現在の実績値・受験資格の確定判定には反映しない。
- 先生は会員の補正後の見込みを参照できる。

### 5.5 級・段の候補表示

- **級**：必要稽古回数まで残り10回を候補表示の目安とする。正式な資格判定は稽古回数・日数・経過年数の有効なAND条件に従う。
- **段**：年3回の審査予定日を、会員ごとの稽古ペースによる到達見込みと照合し、目標とし得る審査日を提示する。固定の「週2回」を全員に適用しない。
- 候補表示は先生による声掛け・検討のための支援情報であり、システムが受験者を自動登録しない。

### 5.6 目標審査日と審査候補アンカー

- 先生は会員への声掛け等を踏まえ、目標審査日を設定し、審査候補としてアンカーできる。
- 「到達見込み」「目標審査日／候補アンカー」「正式受験登録」は別の概念・状態として扱う。
- 稽古ペースや予測が変化しても、先生が設定した目標審査日は自動変更しない。

### 5.7 画面連携と実装方針

- **会員画面**：自分の実績平均・補正用稽古頻度・到達見込み・設定済み目標審査日を参照でき、予測用の補正を入力できる。
- **先生画面**：会員ごとの実績平均・補正値・到達見込み・候補状態・目標審査日を参照し、候補アンカーと目標審査日を管理できる。
- 既存の出席集計・審査基準・DAO／業務境界を再利用し、画面ごとに予測計算を重複実装しない。判定BOXへの独立は将来構想のままとする。
- 予測補正値の保存先や平均の信頼性に関する具体的閾値は、既存データ契約を確認して実装時に確定する。

### 5.8 判定・予測・候補登録のフロー

審査資格の確定判定と、将来の到達予測は別処理とする。以下の図は**論理的な情報の流れ**を示すものであり、新規APIや専用サービスの追加を要求しない。

```text
[審査基準マスタ] ──────┐
                      ├──> [審査資格判定（実績のみ）]
[全出席実績・起算日] ──┘              │
                                     └──> 現在の資格・不足量

[直近3か月の出席実績] ──> [週平均稽古枠数・稽古日数]
                                       │
[会員の予測用補正値] ────────────────────┤
[現在の不足量・経過年数] ────────────────┤
[登録済み審査予定日] ────────────────────┘
                                       │
                                       v
                            [次回審査日予測判定]
                                       │
                                       v
                          [候補となる審査日を提示]
                                       │
                                       v
                           [先生が候補をアンカー]
                                       │
                                       v
                            [目標審査日を共有]
                                       │
                          （正式な受験登録は別操作）
```

会員による予測補正の操作と再計算は、次の流れとする。

```text
直近3か月の出席実績
        │
        v
週平均稽古枠数・稽古日数を別々に算出
        │
        v
実績平均を表示
        │
        ├── 補正しない ─────────────┐
        │                          │
        └── 会員が予測用頻度を補正 ──┤
                                   v
                     資格到達見込みを再計算
                                   │
                                   v
                       審査予定日と照合
                                   │
                                   v
                      到達見込み・候補を表示
```

- 補正前の実績平均を保持・表示し、補正によって出席実績や資格判定を変更しない。
- 予測が困難な場合は、その旨を表示する。候補アンカーや目標審査日を予測の変化だけで自動変更しない。
- **級**は残り10回を候補提示の目安とし、**段**は年3回の審査日程に対して到達見込みを照合する。
- 先生によるアンカーは正式な受験登録ではない。受験登録後の状態遷移は第2章に従う。

## 6. データの責務（論理モデル・名称は実装時に既存命名規約へ合わせる）

| データ | 責務 |
|---|---|
| 審査基準 | 現在級段位→次回級段位、必要回数・日数・経過年数、適用状態 |
| 審査予定 | 審査ID、予定日、区分、実施日、予定状態 |
| 審査対象者／結果 | 会員ID、審査ID、受験級段位、受験状態、合否、正式合格日、起算日、スタック境界 |
| 個別調整 | 会員／審査単位の調整値・対象・理由・操作履歴 |
| 級段位履歴 | 昇級昇段イベント、旧／新級段位、正式起算日、確定者・確定日時、訂正履歴 |
| 出席履歴 | 実際の出席事実。審査処理では更新しない |
| 審査費請求 | 審査対象者・審査との関連を保持し、既存の請求・入金処理へ接続する。発生時点・取消方法は未確定 |

同一審査結果の再送・二重クリックは冪等に扱う。合格確定では「審査結果の確定」「会員級段位と起算日の更新」「級段位履歴の記録」を整合性のある一単位として扱う。部分成功を放置しない。Firestoreのトランザクション等の具体手段は既存DAOの契約確認後に選定する。

既存会員データには過去の審査イベントが存在しない可能性がある。既存の級段位と起算日を移行時に消去・推定補完しない。新機能導入前の履歴は「未登録」と区別する。

## 7. 画面と権限

| 画面 | 参照する情報 | 変更可能な情報 |
|---|---|---|
| 審査・昇級昇段管理（新規・先生用） | 審査予定、受験者、資格、進捗、結果、履歴 | 予定・対象者・調整・結果・正式起算日・確定／訂正 |
| 会員画面（既存改修） | 自分の次回審査、必要／実績日数、資格、受験予定、結果待ち、確定後の級段位 | 原則、審査情報の変更なし |
| 先生出席確認画面（既存改修） | 出席状況に加え、会員の審査進捗、受験予定、結果待ち | 出席操作は維持。審査変更は管理画面へ誘導 |

- 会員画面に他会員の審査情報を公開しない。
- 確定操作・個別調整・訂正は先生の認可を必須とし、画面表示制御だけに依存しない。
- 3画面とも同一の審査状態・判定結果を使用し、画面側で別の資格判定を実装しない。
- 先生も会員一覧および審査対象者候補へ含める。先生自身の結果を誰が確定できるかは権限仕様として別途確定する。
- 先生用出席登録画面を将来廃止する案は検討事項とする。代理登録・訂正など現在の責務を確認するまで、現時点の画面と動作は変更しない。

## 8. 必須要求仕様

### 8.1 先生向け

先生は、先生を含む全会員について次の情報を参照・管理できること。

1. **近日中に審査受験条件を満たしそうな会員の把握**
   - 現在の達成状況と、必要な稽古枠数・稽古日数・経過年数に対する不足量を確認できる。
   - 資格到達済み、近日到達見込み、条件不足、基準または起算日の不足により判定不能、を区別できる。
   - 「近日」の具体的な期間・閾値は運用確認後に定め、画面側で推測しない。
2. **審査日の把握**
   - 今後の審査日程と、会員ごとの受験予定を確認できる。
3. **審査結果の文章記録**
   - 合否とは別に、講評・所見・申し送り等を文章で記録できる。
4. **審査結果日の記録**
   - 審査結果に対応する日付を記録できる。
   - 審査実施日、正式合格日、結果通知日およびシステム確定日時との関係は、級・段の日付モデルと未確定事項に従う。
5. **審査受験条件の閲覧**
   - 次回級段位に適用される基準と、その基準の出所を確認できる。
6. **会員ごとの稽古記録・経過の閲覧**
   - 稽古枠数、稽古日数、経過年数および、それぞれの必要値・実績値・不足値を確認できる。
   - 判定の根拠となった出席記録と級段位起算日を確認できる。

### 8.2 会員向け

会員は、自分自身について次の情報を閲覧できること。他会員の審査情報は閲覧できない。

1. **自分の稽古記録・経過の閲覧**
   - 稽古枠数、稽古日数、経過年数および、それぞれの必要値・実績値・不足値を確認できる。
   - 判定不能の場合は、不足している基準または起算日を確認できる。
2. **審査受験条件の閲覧**
   - 現在級段位から次に受験する級段位と、適用される受験条件を確認できる。

### 8.3 要求範囲の境界

- 会員自身による審査申込、合否の自動確定、級段位の自動更新は、この必須要求には含めない。
- 先生が記録した審査結果文章を会員へ公開するか、および公開時期・範囲は未確定とする。
