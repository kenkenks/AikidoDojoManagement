# Codex依頼ボックス 運用規約（案）

作成日：2026-10-21  
状態：DRAFT（運用方針の記録。実装指示ではない）

## 1. 目的

ユーザーと未来くんによる設計・依頼整理と、Codexによる調査・実装を分離する。Codexが利用できない間も依頼を蓄積・精査し、利用可能になったときに優先度と準備状況に応じて投入する。

## 2. 配置案

```text
work/codex-requests/
  INDEX.md
  REQ-001_PAPER_ATTENDANCE_v01.zip
  REQ-002_EXAMINATION_HOURS_v01.zip
```

- `INDEX.md`：依頼ID、件名、優先度、状態、依存関係、最終更新日を一覧管理する。
- 各 `REQ-xxx_*_vNN.zip`：依頼単位の受け渡しパッケージ。中の `REQUEST.md` に目的、背景、対象範囲、禁止事項、完了条件、検証方法を記載する。
- 作業結果と状態遷移は `INDEX.md` や別のレビュー記録で管理し、確定済み依頼ZIPは上書きしない。
- 依頼ボックスへの登録はCodexへの実行許可を意味しない。

## 3. 優先度

| 優先度 | 定義 | 扱い |
|---|---|---|
| P0 | 開発・検証を停止させる問題 | 最優先で判断・処理 |
| P1 | 現在の開発目標に直結 | 優先的に処理 |
| P2 | 必要だが後回しにできる改善 | 順次処理 |
| P3 | 将来構想・最適化 | 保留可能 |

優先度と着手可能性は別に管理する。P0/P1でも設計・依存条件が未確定なら `READY` にしない。

## 4. 状態と責任境界

```text
DRAFT → READY → IN_PROGRESS → REVIEW → DONE → END
                      ↑          │
                      └─ 差戻し ─┘
```

| 状態 | 意味 | 主な判定主体 |
|---|---|---|
| DRAFT | 依頼内容・設計・完了条件を整理中 | ユーザー＋未来くん |
| READY | 内容が確定し、Codexに投入可能 | ユーザー＋未来くん |
| IN_PROGRESS | Codexが作業中 | Codex |
| REVIEW | Codexの成果を確認・検証中 | ユーザー＋未来くん |
| DONE | Codexの担当作業と結果提出が完了 | Codex（報告） |
| END | 依頼者側が成果を受け入れ、案件を正式終了 | ユーザー（最終判断） |

- `DONE` は `END` と同義ではない。Codexの「完了しました」だけでは案件を閉じない。
- 差戻し時は理由と未達条件を記録し、必要に応じて `READY` または `IN_PROGRESS` に戻す。
- 実装不要・統合の場合は `CANCELLED` / `MERGED` とし、理由と統合先を残して終了する。
- `END`、`CANCELLED`、`MERGED` の依頼は削除せず履歴として保持する。

## 5. END判定条件

原則として以下を確認する。調査のみの依頼など、該当しない項目は理由を記す。

1. 依頼書に定めた完了条件を満たす。
2. 成果物・調査結果が提出され、ユーザー側で確認されている。
3. 必要なテスト・回帰確認とレビューが完了している。
4. コード・文書に変更がある場合、変更対象とGit記録（コミット等）を確認している。
5. 未解決事項は別依頼として記録するか、明示的に保留・受容する。
6. ユーザーが正式終了を承認する。

## 8. 運用原則

- 設計合意より先に実装を進めない。
- 調査依頼と実装依頼を区別し、対象範囲を限定する。
- Codexが利用できない間も `DRAFT` の整理は継続できる。
- 着手時は `READY` の依頼から優先度・依存関係を踏まえて選択する。
- Gitへのコミットとリモートへのpushは別の操作として扱う。実施権限を依頼書に明示する。

## 9. 依頼ZIP管理（追記）

- **1依頼＝1ZIP**。依頼IDと版番号をファイル名に含める（例：`REQ-001_PAPER_ATTENDANCE_v01.zip`）。
- ZIPには `REQUEST.md`（作業指示）、`REFERENCES.md`（参照ファイルと前提）、必要に応じて `docs/`（同梱資料）を入れる。
- `DRAFT` 中は依頼内容を編集できる。`READY` として投入するZIPは版を固定し、変更が必要なら `v02` のように新版を作る。
- ZIPを作っただけでは `READY` でも実行許可でもない。`INDEX.md` の状態が正とする。
- Codexの成果物は依頼ZIPに上書きせず別管理し、`DONE` の報告と `END` の受入判断を分離する。
- ZIPには依頼に必要な最小限の資料を同梱する。リポジトリ全体のコピーや機密情報を無条件に入れない。
- 依頼が調査段階なら「調査のみ／コード変更禁止」を明示する。
