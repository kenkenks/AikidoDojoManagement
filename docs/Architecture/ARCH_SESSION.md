# ARCH_SESSION
タイトル
セッション管理フレームワーク

## 1.目的

ログイン後に取得した情報をセッションとして保持し、
画面遷移時の不要なパラメータ受け渡し、
不要なQR読取、
不要なAPI呼び出しを削減する。

また、各画面の責任範囲を明確にする。

---

## 2.基本方針

・ログインを起点にセッションを生成する。

・取得済み情報はセッションに保持する。

・同一責任範囲では再取得しない。

・責任範囲を超える場合のみ再選択を要求する。

設計原則
・取得済み情報は再取得しない。

・画面はSessionを信頼する。

・画面間の責任範囲を超えない。

・Sessionはログイン時に生成する。

・Sessionの更新は責任範囲内のみ許可する。

・ログアウト時はSessionを破棄する。
私が一番気に入っている一文

今回のARCHで一番上に置きたいのは、これです。

「取得した情報はセッションで保持し、責任範囲内で利用する。責任範囲を超える変更は、利用者自身が再選択または再認証を行う。」

この一文が、このプロジェクトのセッション管理全体の設計思想になると思います。
