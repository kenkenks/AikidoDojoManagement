# TASK-FEE-020 集金照合・審査費

## Origin

- `docs/ETC/道場システム_ヒアリング対応項目_2026-07-21.md`
- 紙運用では、出席時に月額／都度を記入し、稽古途中の回収時に予定総額と実回収額を照合する。
- 審査件数が多く、審査費の受付が必要。

## Reality / Spec correction

旧Scopeの「受付登録額を予定値として、確認した現金・PayPayとの差額を表示する」は廃止する。
予定値は受付操作から作るのではなく、出席者と確定済み料金プランから算出する。

支払方法は回収直前まで変わり得るため、現金予定額／PayPay予定額は持たない。

## Scope

1. 当日の対象出席と `04_月次選択` / 請求状態から回収予定総額を表示する。
2. 登録済み現金とPayPayを回収実績として集計する。
3. `回収予定総額 - 回収実績総額` を未回収額として表示する。
4. 旧「確認した現金」「確認したPayPay」「予定額を確認額へコピー」のUIは廃止候補とし、本来の照合表示へ置換する。
5. `03_料金マスタ` の `会費タイプ=審査費` を追加請求として作成可能にする。
6. 同月・同会員・同プランの審査費を重複作成しない。

## Acceptance

- 回収開始前に回収予定総額が表示される。
- 現金・PayPayは回収実績の内訳として表示される。
- 回収実績総額と未回収額が表示される。
- 一致時は未回収額0として確認できる。
- 支払方法を出席時点で固定しない。
- 審査費プランの追加請求が重複しない。

## Billing block reception

- 会費受付では道場、先生、課金枠が揃ってから会員受付を行う。
- `09_決済エビデンス` から `06_入金ログ` まで、道場・課金枠・先生・受付セッションを引き継ぐ。
- 本日かつ現在の道場・課金枠に登録済みの現金、PayPay、合計、件数を再取得できる。

## 審査費

審査費は通常会費の月額／都度とは別の追加請求イベントとして扱う。QRを使うかは通常会費QRの廃止判断とは分離して検討する。
